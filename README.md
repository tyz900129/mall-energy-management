# 万悦城后勤管理系统

万悦城后勤管理系统是面向商场运营、工程、商管、安保及保洁人员的内部业务平台。系统已从最初的能源管理扩展为涵盖商户与铺位、计量设备、能源用量、工程资料、设施拓扑、业务流程、施工管理、设备巡检、异常通知和系统管理的一体化后勤管理平台。

本文档根据当前代码及生产环境实际功能整理。当前数据库结构版本为 **V49**，更新时间为 **2026-09-29**。

## 一、当前已实现功能

### 1. 工作台

- 展示计费账户、铺位、仓库、已绑定设备铺位和本月提交流程等核心指标。
- 展示系统业务概况和待处理事项。
- 指标按实际业务口径统计，不再展示原平台运行状态。

### 2. 水电费变更流程

支持新商户开户、已有商户增加铺位和已有商户撤柜。当前已实现：

- 商户代码、商户名称、铺位、联系人、联系电话和生效时间采集。
- 联系电话与原计费账户手机号对比，并确认是否变更短信通知号码。
- 铺位计费账户冲突检查，以及已提交撤柜流程后的衔接处理。
- 根据铺位水电设备情况自动生成现场核验任务。
- 手机端现场核验、读数、倍率、照片和时间水印采集。
- 电表、水表照片数量及拍摄内容规则校验。
- OA 提交资料、申请批注、设备表号或序列号、倍率及实际读数生成。
- OA 流程编号和完结备注维护。
- 状态区分待现场核验、待 OA 提交、等待平台处理、已完成等阶段。
- 根据平台同步后的设备与计费账户绑定关系自动判断流程是否完成。
- 超级管理员可复位或彻底删除流程及其关联核验、附件和记录。
- 防止网络卡顿或重复点击生成多条相同草稿。

### 3. 商户施工流程

支持入场装修和撤场施工两种申请。当前已实现：

- 从铺位选择施工位置，并填写施工起止时间。
- 采集商户、施工公司、施工负责人、物业工程专员和商管负责人资料。
- 根据提交人的人员角色自动填充内部负责人姓名和电话。
- 提交后生成固定格式的万悦城商户施工许可证。
- 许可证支持独立打印，包含施工流程二维码。
- 扫描二维码可查看许可证并进入安保、工程或保洁现场巡检。
- 申请人可提交验收申请，验收结果形成验收记录。
- 入场装修验收合格后铺位转为在用，撤场施工验收合格后铺位转为空置，并归档施工流程。

### 4. 施工现场巡检配置

- 分别维护安保巡检、工程巡检和保洁巡检题库。
- 支持正常/异常、是/否、单选、多选、数字和文字题型。
- 支持必填、启用/停用、排序、正常值和“异常必须上传照片”设置。
- 扫描施工许可证后，根据巡检人员权限动态显示可执行的巡检类型和题目。
- 异常答案自动将巡检结果判定为“存在问题”，并形成待整改记录。
- 保存巡检题目快照和答案快照；后续修改题库不会改变历史巡检记录。
- 最近巡检记录可查看当时填写的检查结果、人员和时间。

### 5. 商户账户、铺位与计量设备

- 同步原能源平台的计费账户、设备及账户设备关系。
- 商户账户本地维护商户代码、联系人电话、启停状态和关联铺位。
- 当前商户代码校验、标准账户名称生成及查询通道仍以连续六位数字为标准。
- 支持隐藏停用计费账户。
- 铺位名称根据绑定设备关联的计费账户提取商户名称。
- 铺位保留编码、当前商户、楼层、面积、业态和状态等核心信息。
- 楼层、区域、业态、品类等基础资料采用可管理字典。
- 铺位及基础字典支持 Excel 导入、导出。
- 计量设备展示设备 ID、设备名称、能源类型、通讯地址、序列号、网关、通道名称和产品名称。
- 支持按铺位维护水电设备绑定关系，每台设备只能绑定一个启用的计费账户。
- 支持设备过滤名单；名单设备不参与当前同步，但可按需补采历史账单数据。

### 6. 铺位工程资料

按铺位维护以下工程基础信息：

- 供配电回路、电缆规格、供电端开关和电表位置。
- 是否供水、水表口径及水表安装位置。
- 是否排水、排水管口径及排水管路编号。
- 是否有排油烟、排油烟设备编号。
- 是否有补风、补风机编号。
- 空调设备型号、类型、功率、出风量及实际风口数量。
- 是否使用天然气、燃气口径和自动切断阀位置。

电缆规格、开关规格、电表位置、管径、风机和空调规格均通过基础字典维护。铺位工程资料可与设施拓扑中的铺位节点双向关联。

### 7. 能源用量管理

- 按设备产品类型自动选择测量点，不要求每次同步手工设置。
- 月度用量采用月累计数据同步和计算，提高批量同步速度。
- 日数据分批同步，仅保留近三个月，用于日用量和异常分析。
- 历史月份支持补采，过滤设备仍可保留和补采历史数据。
- 设备可按连营商户、自营商户、超市、总部、酒店等分析维度分类。
- 用量按设备在统计周期内的分组变化拆分，避免整月错误归类。
- 支持周、月、季、半年和年度等维度的用量分析。
- 数据大屏展示趋势、同比、分析维度占比、有效数据设备数量等指标。
- 支持手工录入年月、电费金额、电费用量、水费金额和水费用量。
- 水电账单曲线支持月度、季度、半年和年度同比展示。

### 8. 设施拓扑管理

已实现配电、供水、排水、排油烟和补风机五类独立拓扑。新风与补风在本系统中按同一业务含义管理。

配电拓扑支持变压器、开关、配电箱、终端箱、用电设备等自定义多级节点，并支持双电源输入、备用上级、节点详情和二维码。其他设施拓扑支持节点层级、铺位关联和二维码查看。

### 9. 设施设备巡检

该模块使用独立设施设备台账，不与能源平台水电表强制关联。

- 维护变压器、配电柜、消防栓、空调、供水设备、电梯等设备分类。
- 不同设备分类可关联不同巡检表单。
- 每台设备具有独立二维码，扫码后直接进入对应设备巡检表单。
- 巡检记录保存扫码设备的基础资料快照。
- 支持巡检类型、频率、内容、计划、任务及提醒。
- 支持问题整改管理和巡检数据大屏。

### 10. 异常中心与通知

- 检测计费账户、设备关系、流程预期变化及同步数据异常。
- 区分提示、警告、错误和严重等级。
- 识别每台设备绑定多个启用计费账户等业务异常。
- 已有关联流程且处于合理处理阶段的数据不重复产生错误告警。
- 支持企业微信、飞书和钉钉 Webhook。
- 可维护多个机器人，并按不同通知事件选择一个或多个目标群组。
- 流程、核验、完成通知及异常中心告警均可独立配置通知目标。
- 外部消息中的系统链接统一使用 `https://auto.apperload.com`。

### 11. 用户与权限

系统保留五类基础角色：超级管理员、系统管理员、设备核验员、申请人和只读用户。

同时支持细粒度个人授权：

- 用户继承角色的默认权限。
- 管理员可为单个用户额外授予或明确拒绝某项权限。
- 个人授权支持失效时间、授权原因和变更记录。
- 新注册用户默认无业务权限，需要管理员分配角色或个人权限。
- 登录支持设备指纹自动登录，并允许退出后切换其他账户。

系统管理员默认拥有除用户管理、个人授权和高风险数据迁移外的大部分业务权限；超级管理员拥有完整权限。

### 12. 数据同步、审计与迁移

- 源平台连接信息和同步任务管理。
- 账户、设备、关系、月度用量及近期日数据分批同步。
- 同步批次、进度、成功数、失败数、无数据数及详细日志查询。
- 基础字典、铺位等业务数据导入导出。
- 系统资料一键导出和导入，包含数据库及上传附件。
- 导入失败时不覆盖原数据库，并保留任务错误信息用于排查。
- 关键业务操作写入审计日志。

## 三、技术架构

### 后端

- Java 17、Spring Boot 3.3.5。
- Spring Security + JWT。
- MyBatis-Plus 3.5.9、MySQL 8、Flyway。
- Apache POI 导入导出、ZXing 二维码、OkHttp 外部调用。

### 前端

- Vue 3.4、TypeScript 5.4、Vite 4.5。
- Element Plus 2.7、Pinia 2.1、Vue Router 4.3、Axios 1.6。

### 项目目录

```text
server-spring/
  energy-management/  Spring Boot 后端及 Flyway 脚本
  energy-admin/       Vue 3 管理端
  design/             早期系统设计资料，仅作历史参考
```

## 四、本地开发与构建

后端需要 Java 17、Maven 和 MySQL 8：

```powershell
cd server-spring/energy-management
mvn test
mvn spring-boot:run
```

前端建议使用 Node.js 20 或更高版本：

```powershell
cd server-spring/energy-admin
npm install
npm run dev
```

生产构建：

```powershell
cd server-spring/energy-management
mvn -DskipTests package

cd ../energy-admin
npm run build
```

后端构建产物为 `energy-management.war`，前端构建产物位于 `energy-admin/dist`。

## 五、配置与安全

生产环境的数据库密码、JWT 密钥、平台凭据、Webhook 地址及管理员初始密码必须通过环境变量或安全配置提供，不得写入源码或提交到 Git。

常用配置项：

- `MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_DB`、`MYSQL_USER`、`MYSQL_PASSWORD`。
- `JWT_SECRET`。
- `PLATFORM_CREDENTIAL_SECRET`。
- `ENERGY_DEFAULT_ADMIN_PASSWORD`。
- `ENERGY_PUBLIC_BASE_URL`。
- `ENERGY_UPLOAD_BASE`。
- `ENERGY_MIGRATION_BASE`。
- `ENERGY_CORS_ALLOWED_ORIGINS`。

安全约束：

- `.env`、上传附件、日志、数据库备份和部署包均不得纳入版本控制。
- 平台密码和 Webhook 地址在数据库中加密保存。
- 所有危险操作必须经过权限校验并记录审计日志。
- 数据迁移包包含业务数据及附件，应按敏感资料保管。

## 六、当前边界与后续规划

以下内容尚未作为正式功能交付：

- 海康威视人脸识别门禁 SDK 接入。
- 门禁设备管理、人员人脸同步、有效期管理、访客预约和续期。
- 五位商户代码兼容改造；当前表单和账户名称规则仍按六位商户代码处理。
- 其他后勤业务模块应继续沿用现有“角色默认权限 + 个人细粒度授权”模式扩展。

开发新模块时，应通过新增权限码控制菜单、查看、编辑、管理和高风险操作，避免继续增加大量固定角色。
